переопределение методов и полиморфизм.

## Требования

- Python 3.10 или новее.
- Сторонние библиотеки не требуются.

## Возможности

- Генерация 12-значных номеров счетов и проверка уникальности при открытии через банк.
- Пополнение и снятие средств.
- Статусы: активный, замороженный, закрытый.
- Валюты: RUB, USD, EUR, KZT, CNY.
- Проверка входных данных и обработка ошибок.
- Расчёты с использованием `Decimal`.
- Накопительные, премиальные и инвестиционные счета.
- Регистрация совершеннолетних клиентов, вход и сессии.
- Управление состоянием счетов с проверкой владельца.
- Ночные ограничения, журнал подозрительных действий, поиск и аналитика.

## Типы счетов

### BankAccount — обычный счёт

Реализует общие операции и проверки:

- пополнение баланса;
- снятие в пределах доступных средств;
- проверку статуса счёта;
- получение информации о счёте;
- строковое представление.

Операции пополнения и снятия разрешены только для активного счёта.
Лимит одного снятия — 50000 в валюте счёта. Снятие ровно этой суммы
разрешено; превышение вызывает `InvalidOperationError` без изменения баланса.
Лимит доступен через свойство `withdrawal_limit` и отображается в сведениях
о счёте. Накопительный и инвестиционный счета наследуют этот лимит.

### SavingsAccount — накопительный счёт

Добавляет:

- `min_balance` — неснижаемый остаток;
- `monthly_interest_rate` — месячную ставку;
- `apply_monthly_interest()` — начисление дохода за месяц.

Начальный баланс не может быть ниже неснижаемого остатка.
Снятие ровно до этого остатка разрешено.

Доход рассчитывается по текущему балансу:

```text
Доход = баланс × месячная ставка
```

Например, при балансе 10000 и ставке 1% начисляется 100.

Ставка задаётся долей: `Decimal("0.01")` означает 1%.

Каждый вызов начисления соответствует одному условному месяцу.
Доход добавляется к балансу и учитывается при следующем начислении.
Календарь и минимальный баланс за расчётный период пока не учитываются.

### PremiumAccount — премиальный счёт

Добавляет:

- `withdrawal_limit` — лимит одного снятия без учёта комиссии;
- `overdraft_limit` — допустимую задолженность;
- `fixed_fee` — фиксированную комиссию за успешное снятие.

Настройки по умолчанию:

| Настройка | Значение |
|---|---:|
| Лимит одного снятия | 100000 |
| Лимит овердрафта | 10000 |
| Комиссия | 50 |

Комиссия списывается сверх запрошенной суммы и учитывается при проверке
овердрафта. Баланс может достигать отрицательного лимита, но не уходить ниже.

Пример:

```text
Баланс: 1000
Снятие: 1500
Комиссия: 50
Новый баланс: -550
```

Пополнение погашает задолженность.
При отклонённом снятии баланс не меняется и комиссия не списывается.

По умолчанию лимит премиального счёта вдвое выше обычного:
100000 против 50000. При создании премиального счёта можно задать
собственный положительный `withdrawal_limit`.

### InvestmentAccount — инвестиционный счёт

Хранит отдельно:

- свободный баланс;
- виртуальный портфель с суммами вложений.

Допустимые типы активов:

- `stocks`;
- `bonds`;
- `etf`.

Метод `invest(asset_type, amount)` переводит деньги со свободного баланса
в выбранный тип активов. Он проверяет тип актива, положительность суммы
и достаточность свободных средств.

Снятие доступно только со свободного баланса.
Продажа активов не реализована.

Свойство `portfolio` возвращает копию словаря, чтобы внешнее изменение
полученных данных не меняло внутренний портфель.

Метод `project_yearly_growth(growth_rates)` рассчитывает ожидаемый
годовой прирост. Ставки передаются словарём:

```python
growth_rates = {
    "stocks": Decimal("0.10"),
    "bonds": Decimal("0.04"),
    "etf": Decimal("0.07"),
}
```

Для портфеля из 1000 в stocks, 2000 в bonds и 1000 в etf:

```text
1000 × 10% + 2000 × 4% + 1000 × 7% = 250
```

Метод возвращает прирост, а не итоговую стоимость.
Расчёт не изменяет баланс и портфель.

Ставка обязательна для каждого актива с ненулевым вложением.
Отрицательные ставки разрешены для моделирования убытка.

Все активы и ставки условные. Котировки и внешние API не используются.

## Наследование и полиморфизм

```text
AbstractAccount
└── BankAccount
    ├── SavingsAccount
    ├── PremiumAccount
    └── InvestmentAccount
```

Каждый дочерний класс переопределяет:

- `withdraw()`;
- `get_account_info()`;
- `__str__()`.

Это позволяет вызывать одинаковые методы у разных типов счетов,
получая поведение, соответствующее конкретному классу.

## Система Bank — день 3

### Клиент

`Client` хранит ФИО, дату рождения, 12-значный строковый ID, контакты,
статус (`ACTIVE` или `BLOCKED`) и список номеров счетов.
При создании проверяется возраст не менее 18 лет. Для даты рождения
29 февраля в невисокосном году очередной возраст наступает 1 марта.
ID генерируется на основе UUID; повторный ID при регистрации отклоняется.
Контакты должны содержать хотя бы одну непустую пару строк.
Свойства контактов и списка счетов возвращают копии.

### Операции банка

`Bank` хранит клиентов и счета в памяти. Принадлежность счёта определяется
по ID клиента, а не по ФИО.

| Метод | Назначение |
|---|---|
| `add_client(client, password)` | Регистрация клиента |
| `authenticate_client(client_id, password)` | Проверка пароля и выдача токена |
| `open_account(session_token, account_type, ...)` | Открытие счёта |
| `freeze_account(session_token, account_id)` | Заморозка активного счёта |
| `unfreeze_account(session_token, account_id)` | Разморозка замороженного счёта |
| `close_account(session_token, account_id)` | Закрытие счёта без средств и вложений |
| `deposit(session_token, account_id, amount)` | Пополнение |
| `withdraw(session_token, account_id, amount)` | Снятие |
| `invest(session_token, account_id, asset_type, amount)` | Вложение свободных средств |
| `apply_monthly_interest(session_token, account_id)` | Начисление месячного дохода |

Типы при открытии: `standard`, `savings`, `premium`, `investment`.
Дополнительные настройки проверяются по выбранному типу.
Начальный `balance` задаёт учебные средства; реальный перевод не моделируется.
Метод возвращает сведения о счёте, а не изменяемый объект.

Закрывать можно активный или замороженный счёт с нулевым балансом
и пустым портфелем. Закрытый счёт остаётся в истории и повторно
не активируется. Попытки управлять чужим счётом отклоняются.

### Вход и безопасность

Пароли хранятся как PBKDF2-HMAC-SHA256-хеши с отдельной случайной солью.
После трёх последовательных неверных паролей клиент блокируется,
а все его сессии отзываются. Успешный вход сбрасывает счётчик ошибок.
Разблокировка клиента и срок действия сессии пока не реализованы.

С 00:00 включительно до 05:00 по московскому времени (UTC+3) запрещены
регистрация, открытие счетов, изменение их статусов и денежные операции.
Вход и чтение данных разрешены. Источник времени можно подменить:

```python
from datetime import datetime
from bank.bank import Bank

bank = Bank(
    now=lambda: datetime(2026, 11, 13, 12, tzinfo=Bank.BANK_TIMEZONE)
)
```

Журнал фиксирует блокировку входа, обращение к чужому счёту
и попытку ночной операции. События содержат время, тип, ID клиента
и описание; при ночной регистрации ID отсутствует.
Пароли и токены в журнал не записываются.
`get_suspicious_events(session_token)` возвращает копии только собственных
событий клиента. После блокировки доступ через сессии прекращается.

### Поиск и аналитика

`search_accounts(session_token, ...)` ищет только собственные счета.
Необязательные фильтры: точный `account_id`, `account_type`, `status`, `currency`.
Несколько фильтров применяются одновременно; без совпадений возвращается
пустой список. Закрытые счета также доступны для поиска.

`get_total_balance()` возвращает суммы отдельно по валютам.
`get_clients_ranking(currency)` сортирует клиентов по убыванию средств
в выбранной валюте; при равенстве — по ID.
Учитываются портфель и задолженность. Замороженные счета и средства
заблокированных клиентов включаются, закрытые счета пропускаются.
Клиенты без средств в выбранной валюте получают нулевую сумму.

Аналитические методы являются сводками уровня банка и не проверяют
клиентскую сессию. Роли сотрудников и разграничение доступа к аналитике
в пользовательском интерфейсе пока не реализованы.

## Запуск

Все команды выполняются в PowerShell из корня проекта.

Создайте виртуальное окружение, если оно ещё не существует:

```powershell
py -m venv .venv
```

Запустите нужный модуль:

```powershell
.\.venv\Scripts\python.exe -B -m tests.day1
.\.venv\Scripts\python.exe -B -m tests.savings
.\.venv\Scripts\python.exe -B -m tests.premium
.\.venv\Scripts\python.exe -B -m tests.day2
.\.venv\Scripts\python.exe -B -m tests.day3
```

Активация окружения для этих команд не требуется.

Флаг `-B` отключает создание новых файлов байт-кода.
Существующие папки `__pycache__` он не удаляет.

## Проверки

В `tests` находятся демонстрации с `assert` и автоматические тесты `unittest`.

- `day1.py` — базовые операции и ограничения замороженного счёта.
- `savings.py` — снятие, неснижаемый остаток, пополнение и проценты.
- `premium.py` — комиссия, овердрафт, ограничения снятия и сравнение
  обычного лимита с повышенным премиальным.
- `day2.py` — несколько счетов каждого типа, инвестиции, прогноз
  и полиморфизм.
- `day3.py` — регистрация, счета, доступ, ночной запрет, журнал и аналитика.

В демонстрации дня 3 используется управляемое время: результат не зависит
от настоящего часа запуска. Итог — 7370 RUB: Анна 4450, Иван 2920.

Если условие `assert` нарушено, возникает `AssertionError`
с описанием ожидаемого результата.

Сообщения об ожидаемых банковских ошибках показывают, что запрещённая
операция была отклонена.

Для запуска всех автоматических тестов:

```powershell
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -t . -p "*.py" -v
```

Шаблон `*.py` нужен, поскольку файлы автоматических тестов не имеют
стандартного префикса `test_`. Команда запускает классы `unittest`,
но не вызывает `main()` демонстраций — их запускают отдельно.

Не запускайте проверки с флагом `-O`: он отключает инструкции `assert`.

## Исключения

| Исключение | Причина |
|---|---|
| `BankError` | Базовый класс банковских ошибок |
| `InvalidOperationError` | Некорректные данные или параметры операции |
| `InsufficientFundsError` | Недостаточно доступных средств |
| `AccountFrozenError` | Операция запрещена из-за заморозки счёта |
| `AccountClosedError` | Операция запрещена из-за закрытия счёта |
| `AuthenticationError` | Неверные учётные данные или недействительная сессия |
| `ClientBlockedError` | Доступ клиента заблокирован; наследник `AuthenticationError` |

## Ограничения

- Данные хранятся в памяти и теряются после завершения программы.
- Уникальность номеров проверяется внутри `Bank`; отдельные объекты счетов
  вне банка могут получить совпадающие номера.
- Проверки сессий, владельца и времени действуют при операциях через `Bank`.
  Прямой вызов методов объекта счёта не выполняет проверки банка.
- Денежные значения и ставки передаются через `Decimal`.
- Автоматическое округление денежных расчётов до копеек не реализовано.
- Отображение суммы с двумя знаками не изменяет сохранённое значение.
- Автоматическое начисление процентов по календарю отсутствует.
- Покупка реальных ценных бумаг и продажа виртуальных активов отсутствуют.
- База данных и внешние API не используются.

Проект предназначен для практики ООП и не моделирует все правила
реальной банковской системы.
