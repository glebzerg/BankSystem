# BankSystem

Учебная банковская система на Python: клиенты, четыре типа счетов, очередь
транзакций, аудит, анализ риска и отчёты с графиками.

Проект показывает ООП на связанном примере: абстрактные классы, наследование,
полиморфизм, инкапсуляцию и взаимодействие отдельных модулей.
База данных и внешние банковские сервисы не нужны.

**Начать проще всего с `examples.day6`** — готовой симуляции банка.
Для сохранения отчётов и графиков запустите `examples.day7`.
Сценарии сами создают клиентов и выполняют операции: вводить данные в консоль не нужно.

## Быстрый запуск

Нужен **Python 3.10 или новее**. Команды ниже предназначены для PowerShell
в Windows. Откройте терминал в корне проекта — там, где находятся `README.md`,
`requirements.txt`, папки `bank` и `examples`.

### 1. Создайте окружение

```powershell
py -m venv .venv
```

Если `.venv` уже существует, этот шаг можно пропустить.

### 2. Установите зависимости

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

`matplotlib` нужен для графиков и полного набора тестов. Текстовые отчёты,
JSON и CSV используют стандартную библиотеку Python.

### 3. Запустите симуляцию банка

```powershell
.\.venv\Scripts\python.exe -X utf8 -B -m examples.day6
```

### 4. Сохраните отчёты и графики

```powershell
.\.venv\Scripts\python.exe -X utf8 -B -m examples.day7
```

Окружение активировать не требуется: команды используют Python из `.venv`.
`-X utf8` обеспечивает вывод кириллицы и символов, `-B` отключает создание
новых файлов `__pycache__`. Запускайте примеры без `-O`: он отключает `assert`.

## Что произойдёт после запуска

### Day6 — посмотреть систему в действии

Сценарий создаёт **5 клиентов, 10 счетов и 30 транзакций**. В консоли появляются:

1. Клиенты, счета и начальные балансы.
2. Постановка поручений в очередь.
3. Результаты исполнения, уровни риска и причины отказов.
4. Счета, история и подозрительные операции одного клиента.
5. Топ-3 клиентов, статистика транзакций и общий баланс банка.

Ожидаемый результат: **25 успешных операций, 5 отказов**, общий баланс
**293 749,50 RUB**. Отказы специально включены в сценарий: недостаток средств,
замороженный счёт, превышение лимита и высокий риск.
В конце выводится `День 6: все проверки пройдены!`.

### Day7 — получить файлы отчётов

Сценарий создаёт отдельный банк и формирует отчёты по клиенту, по всему банку
и по рискам клиента. В конце консоль показывает полный путь к результатам:

```text
reports/day7/<время_запуска>/
├── client/
│   ├── report.txt
│   ├── report.json
│   ├── csv/          # Таблицы счетов, операций, истории и сводки
│   └── charts/       # Диаграммы и линии баланса
├── bank/
│   ├── report.txt
│   ├── report.json
│   ├── csv/
│   └── charts/
└── risk/
    ├── report.txt
    ├── report.json
    ├── csv/
    └── charts/
```

Всего сохраняются **3 TXT, 3 JSON, 20 CSV и 8 PNG**.
Откройте `report.txt` для чтения отчёта, CSV — для просмотра таблиц в Excel,
PNG — для просмотра графиков. JSON содержит весь снимок данных.

Каждый запуск Day7 получает новую папку. Предыдущие результаты сохраняются;
сгенерированные файлы Day7 исключены из Git.
Данные банков хранятся в памяти: каждая демонстрация начинает новый сценарий.
Поэтому итоги Day6 и Day7 различаются.

## Как пользоваться банком в своём коде

Создайте файл `demo.py` в корне проекта и вставьте этот пример:

```python
from datetime import date, datetime
from decimal import Decimal

from bank.bank import Bank
from bank.models.accounts import Currency
from bank.models.clients import Client
from bank.models.transactions import TransactionType

# Учебные часы: пример можно запустить даже ночью.
current = datetime(2026, 11, 17, 12, tzinfo=Bank.BANK_TIMEZONE)
bank = Bank(now=lambda: current)

client = Client("Иван Петров", date(1990, 1, 1), {"email": "ivan@example.com"})
bank.add_client(client, "DemoPassword123")
token = bank.authenticate_client(client.client_id, "DemoPassword123")

main = bank.open_account(token, "standard", balance=Decimal("1000"))
savings = bank.open_account(token, "savings")

# Прямые операции выполняются сразу.
bank.deposit(token, main["account_id"], Decimal("100"))
bank.withdraw(token, main["account_id"], Decimal("50"))

# Создание поручения только ставит его в очередь.
transaction = bank.create_transaction(
    token,
    TransactionType.INTERNAL_TRANSFER,
    Decimal("200"),
    Currency.RUB,
    sender_account_id=main["account_id"],
    recipient_account_id=savings["account_id"],
)
print("До обработки:", transaction["status"])  # queued

bank.process_transactions()
result = bank.get_transaction(token, transaction["transaction_id"])
print("После обработки:", result["status"])  # completed

for account in bank.search_accounts(token):
    print(account["account_type"], account["balance"], account["currency"])
```

Запуск:

```powershell
.\.venv\Scripts\python.exe -X utf8 -B demo.py
```

В конце на обычном счёте будет **850 RUB**, на накопительном — **200 RUB**.

Что важно при работе с API:

- Деньги передаются как `Decimal("100.50")`, а не `float`.
- `token` — сессия клиента; она нужна для работы со своими счетами и поручениями.
- `open_account()` возвращает словарь; номер счёта находится в `account_id`.
- Возвращённые словари — снимки. После операции заново запросите данные.
- `get_transactions(token)` показывает поручения, созданные этим клиентом.
  Входящий перевод другого клиента отражается в балансе и его истории.
- `process_transactions()` обрабатывает готовые поручения всего банка.
- Для сохранения аудита, проверки риска и истории используйте операции через `Bank`.

Полезные методы:

| Метод | Назначение |
|---|---|
| `search_accounts(token)` | Свои счета; доступны фильтры по номеру, типу, статусу и валюте |
| `freeze_account(token, account_id)` | Заморозка своего счёта |
| `unfreeze_account(token, account_id)` | Разморозка своего счёта |
| `close_account(token, account_id)` | Закрытие счёта с нулевым балансом и пустым портфелем |
| `get_transactions(token)` | Свои поручения и их текущие статусы |
| `cancel_transaction(token, transaction_id)` | Отмена своего ожидающего поручения |
| `get_balance_history(token, account_id)` | Неизменяемая история свободного баланса своего счёта |
| `get_suspicious_operations(token)` | Свои операции среднего и высокого риска |
| `get_error_statistics(token)` | Статистика ошибок своих денежных операций |

## Какие счета доступны

Тип задаётся строкой в `bank.open_account(token, account_type, ...)`.
Валюта по умолчанию — RUB; также доступны USD, EUR, KZT и CNY.

| Тип | Класс | Особенности |
|---|---|---|
| `standard` | `BankAccount` | Лимит одного снятия — 50 000 в валюте счёта |
| `savings` | `SavingsAccount` | Неснижаемый остаток, проценты; стандартный лимит снятия |
| `premium` | `PremiumAccount` | Лимит снятия 100 000, овердрафт 10 000, комиссия за снятие 50 по умолчанию |
| `investment` | `InvestmentAccount` | Свободные деньги и отдельный виртуальный портфель: `stocks`, `bonds`, `etf` |

Настройки при открытии: `min_balance`, `monthly_interest_rate` для накопительного
счёта; `withdrawal_limit`, `overdraft_limit`, `fixed_fee` для премиального.
Ставка `Decimal("0.01")` означает 1% за условный месяц.
Комиссия премиального снятия списывается сверх суммы.

Начисление процентов: `bank.apply_monthly_interest(token, account_id)`.
Инвестиция: `bank.invest(token, account_id, "stocks", Decimal("100"))`.
Она уменьшает свободный баланс и увеличивает портфель на ту же сумму.

## Транзакции и безопасность

Поручения поддерживают пополнение, снятие, внутренний и моделируемый внешний
перевод. Основной путь статусов:

```text
created → queued → processing → completed
                              → failed
         → cancelled
```

Больший `priority` выполняется раньше. `scheduled_at` задаёт время выполнения
с часовым поясом. Временная ошибка до списания допускает повтор через 60 секунд,
не более трёх попыток всего. Окончательный отказ автоматически не повторяется.
Причина находится в `failure_reason`, ошибки попыток — в `get_transaction_errors(token)`.

Внутренние переводы бесплатны. Внешний перевод списывает сумму и комиссию 1%.
Для перевода между разными валютами банка нужны явно заданные курсы
`Bank(exchange_rates=...)`; пример есть в `examples.day4`.
Комиссия внешнего перевода и конвертация округляются до двух знаков.

Перед выполнением проверяются владелец, состояние участников и риск операции:

| Признак | Условие по умолчанию | Баллы |
|---|---|---:|
| Крупная сумма | От 100 000 RUB, 1 000 USD/EUR, 500 000 KZT или 10 000 CNY | 2 |
| Частые операции | От 5 разных операций клиента за минуту, включая текущую | 2 |
| Новый получатель | Ещё не было успешного перевода этому счёту | 1 |
| Ночное время | С 00:00 до 05:00 по Москве | 1 |

**Низкий риск — 0, средний — 1–2, высокий — от 3 баллов.**
Высокий риск блокирует операцию до изменения балансов.
Повтор одной транзакции не увеличивает частоту как новая операция.
Пороги настраиваются через `RiskAnalyzer`, передаваемый в `Bank(risk_analyzer=...)`.

У банка дополнительно действует ночной запрет: с 00:00 включительно до 05:00
исключительно по Москве изменение данных запрещено ещё до оценки риска.
Вход и чтение доступны. После трёх последовательных неверных паролей клиент
блокируется, а его сессии отзываются. Пароли хранятся как хеши с солью.

## Отчёты и экспорт

Этот код можно добавить в конец `demo.py` из примера выше:

```python
from bank.reporting.builder import ReportBuilder

builder = ReportBuilder(bank, now=lambda: current)
report = builder.build_client_report(token)

print(builder.to_text(report))
builder.export_to_json(report, "reports/day7/manual/client/report.json")
builder.export_to_csv(report, "reports/day7/manual/client/csv")
paths = builder.save_charts(report, "reports/day7/manual/client/charts")
print("Графики:", paths)

bank_report = builder.build_bank_report()
risk_report = builder.build_risk_report(token)
```

| Метод | Результат |
|---|---|
| `build_client_report(token)` | Свои счета, поручения, суммы по валютам и история баланса |
| `build_bank_report()` | Служебная сводка всего банка, комиссии успешных поручений и топ-3 по валютам |
| `build_risk_report(token, start_at=..., end_at=...)` | Свой риск-профиль, подозрительные операции и ошибки за период |
| `to_text(report)` | Строка с русскими таблицами для печати или записи в файл |
| `export_to_json(report, file_path)` | Полный JSON-снимок; возвращает путь к файлу |
| `export_to_csv(report, directory)` | CSV по разделам; возвращает список путей |
| `save_charts(report, directory)` | PNG-диаграммы; возвращает список путей и освобождает фигуры |

Финансовые итоги считают валюты отдельно и различают свободные деньги и сумму
с инвестиционным портфелем. Статистика поручений и их комиссий относится к очереди.
Прямые пополнения, снятия и инвестиции учитываются в истории баланса и риска;
проценты отражаются в балансе без увеличения частоты клиентских операций.

Графики включают круговую диаграмму статусов, столбцы балансов и уровней риска,
ступенчатые линии фактического баланса. Для клиентского отчёта можно передать
`account_id` в `save_charts()`, чтобы ограничить линии одним счётом.
Остальные диаграммы останутся по всему снимку. Окна автоматически не открываются.

Папки создаются автоматически. Повторный ручной экспорт заменяет одноимённые
файлы; разные отчёты сохраняйте в разные папки. Деньги в JSON — строки с точным
значением, даты — ISO 8601 с часовым поясом. CSV использует UTF-8 с BOM,
разделитель `;` и отдельные таблицы портфелей и причин риска.
Для программного чтения CSV укажите `encoding="utf-8-sig"` и `delimiter=";"`.

## Частые вопросы и ошибки

| Ситуация | Что сделать |
|---|---|
| `No module named bank` или `examples` | Перейдите в корень проекта и запускайте пример через `-m examples.day6` |
| Не найден `matplotlib` или `PIL` | Установите `requirements.txt` тем же Python из `.venv`, которым запускаете программу |
| Сообщение о ночном запрете | Для учебного сценария передайте `now`, как в `demo.py`; по умолчанию банк использует реальное московское время |
| В Day6 есть отклонённые операции | Это ожидаемые сценарии; проверьте итоговую строку о прохождении проверок |
| Поручение осталось `queued` | Вызовите `process_transactions()`; отложенной операции нужно дождаться назначенного времени |
| После Day6 не появились файлы | Запустите Day7: он сохраняет результаты и печатает путь к папке |
| После изменения банка отчёт остался прежним | Создайте новый снимок через метод построения отчёта |

Ожидаемые банковские отказы представлены наследниками `BankError`:
например, `InsufficientFundsError`, `AccountFrozenError`,
`AuthenticationError`, `HighRiskTransactionError`.
Их можно обработать через `except BankError` из `bank.exceptions`.
`AuditWriteError` сообщает об ошибке записи аудита,
`ReportExportError` — об ошибке сохранения отчёта или PNG.

## Границы учебной модели

- Клиенты, счета, очередь и истории хранятся в памяти и теряются после выхода.
  Сохранённые отчёты и аудит остаются файлами; восстановление банка из них не реализовано.
- Внешний перевод моделируется списанием; реальные платежи и котировки не запрашиваются.
- Проценты начисляются явно, портфель виртуальный; продажи активов нет.
- Система рассчитана на один поток. Сессии не имеют срока действия, разблокировка клиента не реализована.
- Подмена часов через `Bank(now=...)` управляет банковскими ограничениями, аудитом
  и историей баланса; временные поля `Transaction` пока используют системные часы.
- Служебная аналитика доступна управляющему Python-коду; роли сотрудников не реализованы.
- Проверки доступа, риска, аудит и история банка действуют при вызовах через `Bank`.
- Если запись аудита сбоит после успешной денежной операции, результат сохраняется.
  `AuditWriteError` в таком случае не означает откат списания или пополнения.
- JSON, CSV и PNG заменяются через временный файл каждый отдельно; экспорт набора не является одной атомарной операцией.

Проект предназначен для практики ООП и моделирует банковские правила в учебном виде.
